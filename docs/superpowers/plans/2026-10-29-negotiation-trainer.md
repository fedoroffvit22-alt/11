# Тренажёр переговоров — порядок работ

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** На базе уже собранного локального голосового агента сделать репетицию звонка: человек говорит как оператор, клиент отвечает голосом фразами и возражениями из звонков CRM.

**Architecture:** Сначала текстовый контур, он уже в дереве. Голос подключается тем же T-One и клоном Qwen3-TTS, которые уже выбраны для агента, через узкий порт: тесты его подменяют и устройство не открывают. Обучение на звонках — это разбор карточек (возражение, следующая реплика оператора, итог), не дообучение весов. Живые API CRM, облачный TTS/ASR и шифрование файлов — отдельные планы после того, как локальный контур звонка замкнут.

**Tech Stack:** Python 3.11+, существующие `app/asr.py` (T-One), `app/tts.py` (Qwen3-TTS clone), `app/reply.py` (локальная Qwen в `.venv-llm`, в репетиции клиента не обязательна), `app/train/` (карточки и страница), pytest. Смоук и pytest веса не скачивают.

## Global Constraints

- Секретов в репозитории нет. DashScope и любой облачный ключ код не читает.
- `python -m app` и `pytest` не вызывают `from_hugging_face`, `from_pretrained` и не открывают микрофон.
- `pip install tone` запрещён. T-One только из voicekit-team/T-one, коммит `3c5b6c015038173840e62cea99e10cdb1c759116`.
- Частота ASR — 8000 Гц, моно PCM16. Другая частота — ошибка, без тихого ресемпла.
- Клиент в репетиции говорит фразами из загруженной карточки. Будущее возражение страница не показывает, пока клиент его не сказал.
- Скидку и сумму можно называть только если они уже были в этом звонке.
- `data/` в git не входит.
- Календарных сроков и сметы в этом плане нет: фазы кончаются проверяемым поведением, а не датой.

## Как спецификация ложится на этот репозиторий

Спецификация описывает шесть независимых контуров. Один план на все шесть будет смешивать голос, CRM, шифрование и дообучение. Ниже порядок. Каждый следующий контур начинается, когда предыдущий уже запускается и покрыт тестом.

Решение по архитектуре из таблицы спецификации: локальный контур. Живой диалог и записи звонков остаются на машине. Облако — позже и только как сменный адаптер, выключенный по умолчанию. Это совпадает и с уже принятым стеком агента, и с требованием низкой задержки и приватности.

| Контур из спецификации | Куда встаёт | Когда |
| --- | --- | --- |
| Диалог, возражения, уровень сложности, разбор | `app/train/` | Фаза 0 есть. Уровни — фаза 3 |
| ASR + TTS в реальном повороте реплик | Порт поверх `app/asr.py` и `app/tts.py` | Фаза 1 |
| Загрузка звонков CRM | Сейчас JSON и текст. Дальше файл WAV рядом с расшифровкой | Фаза 2 |
| Отчёт занятия | CSV из уже посчитанного разбора | Фаза 4 |
| Salesforce, HubSpot, Pipedrive, Zoho по API | Отдельный план. Нужны секреты пользователя, в репозиторий они не кладутся | После фазы 2 |
| ElevenLabs, Google, Azure, Yandex, Whisper как основной голос | Не ставим основным. У агента уже приняты T-One и клон Qwen3-TTS | Адаптер только отдельным планом, по умолчанию выключен |
| Fine-tuning TTS/LLM | Не делаем. Учит карточка: реплика вместе с итогом звонка | Не эта ветка |
| AES-256 для файлов, GDPR-журнал согласий | Отдельный план, когда появится хранение аудио дольше сессии | После фазы 2 |
| WER и MOS | Не рисуем цифры без размеченного набора и прослушивания | Отдельный замер, не экран продукта |
| Нативное приложение Swift / AVSpeech | Страница `python -m app.train` на Mac. AVSpeech русский клон не заменяет | Обёртка — отдельный план, если страницы мало |

Голос оператора в `app/file_run.py` и `scripts/live_session.py` не переписывается. Там модель отвечает как оператор. В репетиции роли наоборот: человек — оператор, карточка — клиент.

## Фаза 0. Текстовый звонок — уже в дереве

Сделано и покрыто `tests/test_crm_import.py`, `tests/test_rehearsal.py`, `tests/test_train_http.py`.

- Выгрузка JSON (`calls[]`) и текст `Оператор:` / `Клиент:`, несколько карточек через `---`.
- Из реплик клиента собираются возражения: цена, время, «подумаю», чужое решение, «уже есть», «не интересно», «пришлите», доверие.
- Человек представляется, клиент поднимает возражения по порядку карточки. Два слабых ответа — клиент завершает звонок. Закрытые — конкретный шаг.
- Страница `http://127.0.0.1:8765/`: библиотека, звонок, разбор. Учебные звонки в `examples/crm/sample-calls.json`.
- Веса, микрофон и облако этот пакет не трогает.

Проверка: `python3 -m pytest -q` и `python3 -m ruff check app tests`.

## Фаза 1. Голосовой поворот, устройство в тесте не открывается

**Interfaces:**
- Consumes: `Rehearsal.say(text: str) -> None`, `Rehearsal.snapshot() -> dict[str, object]`, `Rehearsal.transcript`
- Produces:
  - `class Heard: text: str`
  - `class Spoken: text: str; wav: bytes`

## Фаза 2. Аудиофайл из CRM в ту же карточку

Отдельный план, когда фаза 1 зелёная.

Вход: моно PCM16 8000 Гц, либо стерео, где левый канал — оператор, правый — клиент. Рядом обязательна расшифровка в уже принятом JSON или тексте, пока веса не загружены. Без расшифровки и без явного `CALL_CENTER_LOAD_WEIGHTS=1` команда завершается ошибкой и файл в библиотеку не пишет. Так смоук остаётся без скачивания моделей.

Карточка после разбора — тот же `CrmCall`. Новый тип хранилища не заводим: библиотека остаётся `data/train/library.json`, аудио лежит рядом и в git не входит.

## Фаза 3. Уровни сложности

Отдельный план. Три значения на сессию, не новый диалоговый движок:

- `basic` — подсказка до ответа, клиент ждёт два промаха.
- `medium` — подсказка после ответа. Так страница работает сейчас.
- `hard` — подсказки нет до конца звонка, клиент завершает разговор после одного промаха.

Промпт из спецификации (руководитель, B2B, возражает по цене и срокам) становится текстом уровня, а не вторым чат-ботом. Фразы по-прежнему берутся из карточки.

## Фаза 4. Отчёт занятия

Отдельный план. `GET /api/sessions/{id}` уже отдаёт разбор. Фаза добавляет `python -m app.train report --out занятие.csv`: карточка, итог, закрыто, сказано, виды возражений. Это и есть метрика успеха диалога из спецификации, которую можно посчитать без прослушивания.

## Что не делаем в этих фазах

Живой OAuth к Salesforce, HubSpot, Pipedrive и Zoho. Пока человек кладёт выгрузку файлом. Ключ CRM в репозиторий не попадает.

Облачный синтез и распознавание как путь по умолчанию. Русский контур уже собран локально. Чужой API появится только отдельным адаптером `VoicePort`, выключенным, без ключа в дереве.

Дообучение весов на записях. Для тренажёра достаточно карточки: какое возражение прозвучало, что ответил оператор, чем звонок кончился.

Шифрование аудио на диске и журнал согласий. Их план пишется вместе с хранением записей дольше одной сессии, а не раньше.

WER, MOS и бюджет в рублях. Это измерения и смета, не задачи этого дерева. Задержку фазы 1 меряем как время `play_operator_audio` на подменённом порте; миллисекунды живого Mac-прогона снимаются только явным прогоном с весами.
